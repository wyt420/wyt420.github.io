## 业务背景

不同岗位关心的首页信息不同：管理人员关注 KPI 和待办，现场人员更关心今日计划与快捷入口。因此首页不能再是一套固定布局。

## 功能设计

首页拆为 KPI、待办日历与快捷入口、任务与通知、今日计划等独立模块。编辑模式支持拖拽排序和显隐设置，菜单模式、收藏和模块布局由 Pinia 集中管理，并按用户 ID 写入本地缓存。

## 遇到的问题

功能上线后，旧用户浏览器中仍保存着已经下线的模块 ID；有些模块也发生过改名。如果直接读取旧数组，可能出现空白区域、重复模块或新版模块永远不显示。

## 解决方案

读取缓存时先执行迁移：旧 ID 映射到新 ID，过滤已下线项，去重，再补齐新版默认模块。最终结果才进入 store。这样版本升级不要求用户手动清空缓存。

拖拽时只更新顺序，不直接操作业务组件内部状态；模块显隐也保留顺序信息，使用户再次开启模块时仍回到原位置。

## 验证

- 新用户使用默认布局；
- 老用户的旧 ID 能正确迁移；
- 两个账号在同一浏览器上保存不同偏好；
- 隐藏后恢复模块，位置和内容正常；
- 接口加载失败不影响其他首页模块。

## 项目经历表述

> 将 MES 首页拆分为可编排业务模块，使用 Pinia 按用户持久化顺序与显隐偏好，并设计旧配置迁移与默认项补全机制，保证版本升级后的布局兼容性。
